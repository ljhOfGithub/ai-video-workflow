# AI 视频制作与验收手册

## 1. 把需求写成可以核对的交付条件

先写一句观众看完能做什么。再确认用途、平台、时长、成片画幅、人物、声音来源、字幕、需要保留的工程和封面。用探测工具读取实际素材的尺寸、帧率、时长和音轨。涉及参考片时，记录来源和可使用范围，确定需要借鉴的是镜头节奏、交互方式还是叙事顺序。

## 2. 让每个镜头发生一件观众看得见的事

短教程可用「先给结果 → 展示操作 → 给出响应 → 解释结果」。例如，光标点下保存按钮，按钮进入保存中，随后界面显示已保存，旁白提示观众在哪儿确认。需要讲错误时，让错误提示对应真实触发条件，再演示修正后的响应。

参考片改编先核对完整台词和镜头时间。逐句改写时，给每句留一个对应行，保留信息顺序、逻辑与事实，用自己的表达。把别人的个人成绩和实测数字视为需要核验的独立事实。动作、表演提示、制作状态放进分镜记录。片中保留观众需要的文字。

用[分镜表](../skills/ai-video-production/references/storyboard.md)和[逐句改写与配音表](../skills/ai-video-production/references/adaptation.md)记录。

## 3. 先定关键画面和声音节奏

对话题、操作中段、反馈状态和结尾分别做关键图。画幅改变时重新安排主角、字幕和界面。可以用竖屏上下各约 12.5%、左右各至少 8% 作为构图初始参考，最终以目标播放器叠层、最长字幕和主体运动边界为准。涉及走位、追逐或卡点时，关键图之外还要用能播放或拖动的预览验证动作。

按语义短句记录配音起止、句内停顿和重点词。默认用自己的录音或有明确授权的声源。自然讲解保持稳定，重音留给关键信息。按句修正节奏，防止整段变速掩盖局部停顿或截断发音。改动配音后复查对应字幕和动作时点。

封面与成片画幅可以不同。若同时交竖版 3:4 和横版 4:3，分别排版，验收实际像素尺寸和缩略图可读性。

## 4. 按制作目标选工具

- 真人口播剪辑以转写和剪辑时间线为主。保留自然停顿，重点检查断句、剪切口、字幕和背景声。
- 产品教程或像素互动以动作和界面状态为主。一个操作要对应一个看得见的反馈，光标、角色和音效按同一时间线排列。
- 使用 Hypit 时，保留可编辑工程、编排输入、Build 标识、执行日志和实际导出的结果。用交付文件的哈希核对结果。短测试先证明本机环境和执行器可以运行，再进入完整制作。
- 使用 MotionGit 模板时，保存原包、版本、许可和资源清单，阅读包内 `motion.json`，用替换后的参数跑预览，核对真实导出。模板图层与自制图层各自记录来源。

[Skills 与工具索引](skills.md)提供入口。

## 5. 在实际导出文件上验收

1. 技术：用 `ffprobe` 读取视频和音频规格，用 `ffmpeg` 完整解码。记录时长、像素、帧率、音轨、解码结果和交付文件哈希。
2. 画面：以每 0.5 秒一帧检查字幕、标题、安全区及异常文字。切换、转场、短闪和运动极限另做定点或逐帧复核。
3. 声音：从头听一遍，复核口播、字幕同步、剪切口、停顿、人声遮蔽和响度。对疑似漏字的局部复听或再转写。
4. 内容：核对实际出现的操作和界面响应，确认素材权利及画面中是否意外显示内部说明或个人信息。
5. 播放：在目标播放器打开最终 MP4，测试开始、拖动和结尾。写明通过范围、警告及未验证项。

发现问题时记录时间、所属分镜、预期状态、实际现象和重跑结果。重新导出后重复受到修改影响的检查，再核对最终文件的规格和完整解码。参考片改编可以保留逐帧时间映射，按镜头核对节奏、构图、切换和替换区域。

[验收模板与 OCR 用法](../skills/ai-video-production/references/qa.md)

## 6. 交付能再次打开的产物

交付 MP4、可编辑工程、配音或字幕、所需封面和简短验收记录。将脚本、数据和素材留在可重建的位置，写明工具版本及再导出方法。分享给其他人时可以提供可下载的 ZIP 或 GitHub 版本链接，用本地实际打开的文件确认交付。
